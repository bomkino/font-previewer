# Security

Font files, Study documents, dropped folders, renderer messages, recovery data, and export destinations are untrusted input.

Do not disclose a suspected vulnerability in a public issue. Use the repository’s **Security** tab and private vulnerability-reporting flow. Include the affected commit, minimal reproduction steps, impact, and only proof-of-concept material that is safe to share.

If GitHub private reporting is temporarily unavailable, contact the repository owner through an existing private channel rather than publishing details.

The active threat model and release controls are documented in [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md), [`docs/QA.md`](docs/QA.md), and [`docs/maintenance/RELEASE_POLICY.md`](docs/maintenance/RELEASE_POLICY.md). Historical programme security material remains under `docs/programme/handover/` and must not override current repository truth.
