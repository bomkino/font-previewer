# Font Previewer v0.1.0-rc.7

This candidate gives Simple two independent font sets: **Headlines + subheadlines** and **Body Copy**. Add fonts, see pages, tune a case or style, then export either set or both. Studio continues to use the same Study.

## Two sets, one Study

- Headlines keeps four-up colour Boards and optional 12-font index pages. Body Copy keeps one font per reading page, authored samples, custom copy, and one matched reading size across its included fonts.
- Each set has its own Candidates, copy, and sizing policy. Switching sets does not replace the other set's work.
- **Duplicate font** creates an independent case/style variant within a set. **Copy to Body Copy / Headlines** creates an independent Candidate in the other set without duplicating its Source binary.
- Both-set export writes Boards, optional Index pages, and Body Copy pages into one transactional Handoff. Every included Candidate is exported, not only the current preview batch.
- Saving a Studio comparison retains its displayed custom text in an independent Recipe. Reopening restores that Recipe, Candidate tray, and comparison policy without rewriting either Simple set's copy or sizing.

## Variable fonts and index pages

- Single-face variable fonts import as one Face with default axes and named styles, instead of treating every named instance as a separate broken Face.
- Named style selection applies the complete coordinate set. Duplicate Candidates can retain different cases and axis settings independently.
- Existing variable Candidates are preserved and can use the same supported single-face Source. TTC, OTC, and DFONT collections remain metadata-only.
- Index specimens use measured text bounds for centering, including incomplete final pages. Simple PNG rendering carries each Candidate's variation and feature settings.

## Bounded preview and export work

- Preview and Tune browse 12 Candidates at a time. The Simple interactive registry retains at most 24 Source resources across those visible batches and starts at most four font loads concurrently.
- Unchanged Source resources survive copy, casing, and axis edits; leaving a batch releases resources no longer needed.
- PNG pages render sequentially, temporary export fonts and canvases are released, and the shared Body Copy fit is calculated once per immutable export runtime.
- Export first commits the focused text edit, including an unfinished Study title, then keeps the Study unchanged until the transaction finishes. Native Mac Quit and window close are blocked during export.
- Simple's **Cmd-E** menu route exports the current set and honours the visible Source-copy acknowledgement. Studio retains its full Handoff preferences.

These are implementation bounds and lifecycle changes, not measured reference-hardware latency or RAM improvement claims.

## Study compatibility

Study v5 stores the two set configurations and Candidate membership. Opening v4 preserves existing Candidates in Headlines and starts Body Copy empty. Save to retain v5; keep the original document if you need to reopen it with `rc.6`, which cannot read the new schema.

No font is installed, modified, or copied automatically. Source copying remains explicit and permission-gated.

## Installation boundary

- macOS 13+ Apple Silicon: hardened runtime and ad-hoc signature; no Developer ID or notarisation. Verify checksums before using macOS **Privacy & Security → Open Anyway** when required. Do not disable Gatekeeper globally.
- Ubuntu/Debian x64: hosted X11 and native Wayland/Ozone evidence are required for the exact candidate SHA; independent-machine acceptance remains pending.
- Browser build: development fallback only.

## Known limitations

This candidate does not claim attended VoiceOver or Orca acceptance, human approval of every layout/typeface/script relationship, independent clean-machine reconstruction, universal platform behavior, broad hostile-font containment, a real induced WKWebView content-process termination, or Apple notarisation. Those remain human, stable-release, or stronger-support gates.
